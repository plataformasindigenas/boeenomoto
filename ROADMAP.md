# Boe Eno Moto — Roadmap

Things we know need to happen, roughly ordered by value and urgency.
Updated 2026-04-15.

## Audio coverage

Current state (terradoc 0.8.0, commit `2e2b3e8`): **333 / 4693 entries
have audio (7.1%)**, 394 WebM files in `data/audio/`. The field worker's
archive at `~/bororo` was the source. The import tooling lives (gitignored)
at `scripts/import_audio_archive.py` and is idempotent.

### Low-hanging fruit

1. **Recover the 112 dropped dictionary rows.** They were removed during
   the TSV cleanup because they had missing/invalid `pos`. The full list
   is in `data/audio/_dropped_rows.tsv` (also gitignored). Decide on a
   default `pos` (probably `LEX`), patch the rows in the source TSV, and
   we get 4805 entries again.
2. **Triage the 389 unmatched lex archive files.** They're real recordings
   whose filenames don't match any current entry. They stay in `~/bororo`
   untouched. Open `data/audio/_import_report.md` side-by-side with the
   dictionary and assign by hand — realistic recovery is another 100–200
   entries. Could push coverage from 7% to roughly 11–12%.
3. **Audit suspicious `recordings.yaml` mappings.** A handful of the 135
   matches folded in from the collect_wav inventory look wrong
   (e.g. `aregodu.webm → areia`). Spot-check the ones flagged in the
   import report and either confirm or unlink them in `recordings.yaml`.

### Larger unknowns

4. **Ask the field worker about the missing ~4400 audio files.** The
   cleaned TSV has 4693 entries; we have audio for 333. The TSV originally
   marked almost all entries as having audio, so a bigger archive almost
   certainly exists somewhere — on a drive, another laptop, or still in
   the field. This is by far the highest-leverage next step for community
   impact.

### Cleanup after everything's migrated

5. **Sunset the `recordings` module and `recordings.yaml`.** Once we're
   confident `data/audio/` carries everything it should, delete the old
   collect_wav-style inventory under `docs/recordings/` and remove
   `recordings.yaml`. The `attach_recordings_to_dictionary` function in
   terradoc can stay as a compatibility shim or also be removed.

## Repository hygiene

### docs/ tracking problem

The `.gitignore` contains `docs/` plus `!docs/.gitkeep`, but the entire
`docs/` tree is **tracked** in git anyway — the ignore rule only applies
to new untracked files, not files that were already added at some point.
Consequence: every time anyone runs `scripts/build.sh`, ~500 HTML/JSON
files show up as modified and pollute `git status`, and real work gets
buried under build noise.

Fix (one-shot, high impact):

```bash
git rm -rf --cached docs/
git commit -m "Stop tracking built output; docs/ is regenerated by build.sh"
```

After that, the existing `.gitignore` rule will actually take effect.
Deployment needs to happen from `scripts/build.sh` output or a CI job,
not from committed files. Deserves its own conversation because it
changes how the site gets to production.

### Pre-existing stragglers (not from today's work)

These showed up while triaging `git status` and are worth sorting out:

- **`scripts/build.sh` mode**: filesystem lost the executable bit
  (`100755 → 100644`). Content is identical. Fix: `chmod +x` and stage.
- **`uv.lock` (untracked)**: someone ran `uv` here. Either add it to the
  project and commit, or add it to `.gitignore`.
- **`fullpage.png`, `fullpage2.png` (untracked)**: two screenshots in the
  repo root. Move them or delete them.
- **`raw_corpus/`, `raw_dicionario.tsv`, `raw_especies.xml`,
  `raw_fauna_cards.html` (untracked)**: raw source files that
  **enawenenawe's preparation scripts read via `../boeenomoto/`**. This
  is the coupling flagged in `AGENTS.md` as an urgent roadmap item:
  *"Independent raw data per site"*. Fix is to move the raw data into
  `enawenenawe/` and update its prepare scripts so boeenomoto doesn't
  secretly host another site's source data.

## Data quality

### Dictionary

- **Missing `pos` values on 112 rows** (see above — gated on deciding a
  default).
- **Missing numeric `id` on 126 rows**: today's cleanup auto-assigned new
  ids from `max(id)+1`. Those auto-assigned ids are now in the committed
  TSV and should be stable going forward, but the source of the gaps in
  the original TSV is unknown and worth investigating.

### Known suspicious matches

- `recordings.yaml` row 5 (`0005_elizete_buregi.webm`) is mapped to
  dictionary id 1100 (`burududurewu`) — looks questionable.
- `recordings.yaml` row 6 (`0006_elizete_aregodu.webm`) is mapped to
  dictionary id 298 (`areia`) — also suspicious.

Both were created by `scripts/inventory_recordings.py` before today's
work. Honored as-is during the import per the "don't lose anything" rule,
but they should be reviewed before sunsetting `recordings.yaml`.

## Cross-platform work (terradoc-wide)

These affect the terradoc engine, not just boeenomoto — tracked here only
because they were surfaced while working on boeenomoto. Some are already
in `AGENTS.md`'s global roadmap.

- **Give enawenenawe its own `data/audio/`** following the 1D convention
  now that terradoc 0.8.0 supports it. The 43 `.webm` files already in
  `enawenenawe/docs/audio/` can be moved to `data/audio/<slug>.webm` with
  no code changes — the cross-linker picks them up automatically.
- **`scripts/build.sh` is broken on a fresh clone until
  `pip install -r requirements.txt` is run with the matching terradoc
  version.** Not a new issue, but the 0.8.0 release reminds us it exists.
  A `make install && make build` wrapper or a nox / just recipe would
  make onboarding less fragile.
